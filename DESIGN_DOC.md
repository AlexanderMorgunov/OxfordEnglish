# Design Document — интерактивное приложение для изучения английского (A2→B1)

**Версия:** 0.1 (черновик для агента-разработчика)
**Автор идеи:** frontend-разработчик, 3+ года опыта
**Целевой пользователь v1:** сам автор (A2, цель — B1/B2, американский английский)
**Модель распространения:** личное использование + open source (бесплатно для всех)
**Стек:** React + TypeScript

---

## 0. TL;DR для агента

Мы строим **офлайн-first веб-приложение (PWA)** для системного изучения английского уровня A2→B1, построенное вокруг понятия «день обучения» (learning day). Каждый день = связка из 4 модулей: чтение → грамматика → практика → аудирование, закрываемая чекпоинт-тестом.

Ключевое архитектурное решение: **движок и контент полностью разделены**. Приложение — это «плеер» для контент-паков. В публичный репозиторий не попадает ни один защищённый авторским правом материал. См. раздел 1 — он определяет всю дальнейшую архитектуру, читать первым.

---

## 1. Контент и лицензии — определяющее ограничение

### 1.1 Проблема

Исходная идея — взять тексты, изображения и аудио из American English File 2 (Oxford University Press) и опубликовать приложение на их основе в открытом доступе.

Это невозможно сделать легально. AEF — коммерческий учебник; тексты, иллюстрации, фотографии и аудиозаписи защищены авторским правом OUP. Публикация приложения (даже бесплатного и некоммерческого), содержащего эти материалы, — это распространение чужого произведения без лицензии. Open source здесь ухудшает ситуацию, а не улучшает: репозиторий публичный, ассеты лежат в git-истории, DMCA-удаление репозитория — стандартный и быстрый исход. Аудиофайлы в этом смысле самая рискованная категория: они распространяются OUP по отдельной лицензии вместе с учебником.

**Важно:** это не запрет на проект. Это ограничение на то, что попадает в публичный артефакт.

### 1.2 Что copyright НЕ покрывает

Это принципиально: **последовательность грамматических тем и уровневая методика — не объект авторского права**. Факт, что курс уровня A2→B1 идёт в порядке «verb be → past simple → comparatives → present perfect», — это методическая логика, отражающая CEFR, а не собственность OUP. Оглавление (scope & sequence) курса опубликовано открыто на сайте Oxford и в описаниях магазинов.

Поэтому мы **легально можем**:
- следовать той же последовательности тем и тому же уровню;
- строить те же типы упражнений (gap-fill, multiple choice, dictation — это форматы, а не произведения);
- писать собственные тексты и предложения на те же темы;
- использовать материалы с открытыми лицензиями и в общественном достоянии.

**Не можем:** копировать тексты AEF, сканировать иллюстрации, паковать в репозиторий их аудио.

### 1.3 Архитектурное решение: Content Adapter

Приложение реализует **двухрежимную модель контента**. Это не компромисс — это правильная архитектура, которая заодно решает юридический вопрос.

```
┌─────────────────────────────────────────────────┐
│                  APP ENGINE                     │
│   (React, рендерер уроков, SRS, прогресс, AI)   │
│         — это то, что в open source              │
└────────────────────┬────────────────────────────┘
                     │  Content Pack API (JSON schema)
        ┌────────────┴────────────┐
        │                         │
┌───────▼─────────┐      ┌────────▼──────────────┐
│  PUBLIC PACK    │      │   LOCAL PACK          │
│  в репозитории  │      │   НЕ в репозитории    │
│                 │      │   (.gitignore)        │
│ • свои тексты   │      │ • материалы, которыми │
│ • VOA (PD)      │      │   пользователь владеет│
│ • Tatoeba CC-BY │      │   легально            │
│ • свои упр-я    │      │ • импортируется       │
│                 │      │   локально, у себя    │
└─────────────────┘      └───────────────────────┘
```

**Режим A — Public Pack (то, что публикуется).** Собственный контент, написанный нами, плюс материалы с открытыми лицензиями. Идёт в репозиторий, работает «из коробки» для любого, кто установил приложение.

**Режим B — Local Pack (личное использование).** Приложение умеет читать контент-пак из локальной папки пользователя. Пользователь, легально купивший учебник, сам наполняет эту папку своими материалами на своей машине. Пак попадает в `.gitignore` и никогда не публикуется. Это стандартная модель «BYOC — bring your own content», по которой работают Calibre, Jellyfin, LinguaCafe, Anki: софт распространяется пустым, контент приносит пользователь.

Для автора это означает: **лично ты получаешь ровно то приложение, которое хотел** — со своими материалами по AEF 2, картинками и аудио. Но публикуешь только движок и открытый контент-пак.

### 1.4 Источники открытого контента для Public Pack

| Источник | Лицензия | Что берём |
|---|---|---|
| **VOA Learning English** | Public domain (гос. материалы США) | Тексты, MP3, видео, фото. Есть уровневые серии для learners. Требует указания источника. Главный источник аудирования для нас. |
| **Tatoeba** | CC BY 2.0 FR (тексты); аудио — лицензия на выбор диктора | Предложения-примеры с переводами на русский. Идеально для упражнений и SRS-карточек. Нужна атрибуция. |
| **Storybooks ESL / OER Commons** | открытые лицензии (проверять поштучно) | Простые истории для reading-модуля. |
| **Собственные тексты** | наша лицензия | Ключевой актив. Тематика — жизнь разработчика, как в прототипе. |
| **Изображения** | Unsplash / Pexels / Openverse (CC0/CC BY) | Замена иллюстрациям учебника. |

**Правило для агента:** каждый элемент контента в Public Pack обязан иметь поле `license` и `attribution` в манифесте. Валидатор контента (см. 4.4) падает с ошибкой, если поле пустое.

### 1.5 Собственный контент как конкурентное преимущество

Отдельно стоит сказать: писать свои примеры — не «вынужденная замена», а сильная сторона продукта. Прототип это уже показал: `I deployed the app yesterday`, `the build didn't pass` — грамматика цепляется за знакомый контекст и запоминается лучше, чем нейтральные учебные предложения. Ни один существующий курс не даёт A2-грамматику на материале из жизни фронтендера. Это ниша, в которой приложение уникально и которую есть смысл занять.

## 2. Цели и не-цели

### Цели v1
- Дать структурированный ежедневный маршрут обучения A2→B1.
- Закрывать 4 навыка: чтение, грамматика, практика (письменная/лексическая), аудирование.
- Двуязычие: объяснения и формулировки заданий переключаются EN ⇄ RU **на уровне отдельного блока**, не глобально.
- Долговременное запоминание через интервальные повторения (FSRS).
- Прозрачные метрики: где пробелы, что повторить.
- Работать офлайн, без обязательного бэкенда и регистрации.

### Не-цели v1
- Распознавание речи и оценка произношения (сложно, требует отдельного исследования → v2).
- Социальные функции, лидерборды, друзья.
- Мобильные нативные приложения (PWA закрывает потребность).
- Собственный бэкенд с аккаунтами (только локальное хранилище; синк — опционально в v2).

## 3. Информационная архитектура

### 3.1 Иерархия контента

```
Course (курс, уровень A2)
└── Unit (юнит / «File», ~1 неделя)
    └── Day (день обучения, 30–60 мин)
        ├── Section: reading      (текст + картинка + словарь)
        ├── Section: grammar      (правило EN/RU + примеры)
        ├── Section: practice     (упражнения, типы см. 5.3)
        └── Section: listening    (аудио + задания)
    └── Checkpoint (тест по юниту)
```

Порядок секций внутри дня **конфигурируется в контенте**, не захардкожен. Дефолтный порядок для v1 — рекомендую такой:

**grammar → reading → listening → practice**

Обоснование: правило сначала даёт «крючок», на который навешивается всё остальное; чтение показывает грамматику в живом контексте; аудирование — то же на слух; практика в конце закрепляет всё разом и служит естественным завершением дня. Порядок «reading → grammar» тоже рабочий (индуктивный метод, как в самом AEF), поэтому это поле в схеме, а не константа.

### 3.2 Экраны приложения

| Экран | Роль |
|---|---|
| `/` Dashboard | Сегодняшний день, стрик, что повторить (SRS-очередь), быстрый вход |
| `/course/:unitId/day/:dayId` | Основной экран обучения, вертикальный поток секций |
| `/review` | Сессия интервальных повторений (карточки) |
| `/checkpoint/:unitId` | Тест по юниту |
| `/progress` | Метрики, слабые места, история |
| `/vocabulary` | Личный словарь, статусы слов |
| `/settings` | Язык интерфейса, AI-ключ, импорт контент-паков, экспорт данных |

## 4. Модель данных

### 4.1 Принципы

- Контент — **декларативный JSON**, никакой логики. Добавить день = добавить файл.
- Схема валидируется через **Zod** на этапе загрузки и в CI.
- Прогресс пользователя хранится **отдельно** от контента (IndexedDB), связывается по ID.
- Все ID стабильны и человекочитаемы: `u02.d03.ex.gap.01`.

### 4.2 Схема контента (TypeScript)

```ts
// ---------- локализуемый текст ----------
type LocalizedText = {
  en: string;
  ru?: string;          // опционально; если нет — переключатель RU скрыт
};

// ---------- курс / юнит / день ----------
interface Course {
  id: string;
  title: LocalizedText;
  level: 'A1' | 'A2' | 'B1' | 'B2';
  license: LicenseInfo;      // обязательно
  units: Unit[];
}

interface Unit {
  id: string;                // "u02"
  title: LocalizedText;
  days: Day[];
  checkpoint?: Checkpoint;
}

interface Day {
  id: string;                // "u02.d03"
  title: LocalizedText;
  estimatedMinutes: number;
  sections: Section[];       // порядок = порядок прохождения
  tags: SkillTag[];          // для аналитики слабых мест
}

// ---------- секции ----------
type Section =
  | ReadingSection
  | GrammarSection
  | PracticeSection
  | ListeningSection;

interface ReadingSection {
  type: 'reading';
  id: string;
  title: LocalizedText;
  image?: MediaRef;
  blocks: ReadingBlock[];    // абзацы
  glossary: GlossaryEntry[]; // слова для подсветки и SRS
}

interface ReadingBlock {
  id: string;
  en: string;
  ru?: string;               // параллельный перевод, показывается по кнопке
  audio?: MediaRef;          // озвучка абзаца, опционально
}

interface GrammarSection {
  type: 'grammar';
  id: string;
  title: LocalizedText;
  rule: LocalizedText;       // основное объяснение, EN + RU
  patterns: {                // формулы: "didn't + base form"
    label: LocalizedText;
    formula: string;
    examples: { en: string; ru?: string; highlight?: [number, number] }[];
  }[];
  pitfalls?: LocalizedText[];  // типичные ошибки русскоязычных
}

interface PracticeSection {
  type: 'practice';
  id: string;
  title: LocalizedText;
  exercises: Exercise[];
}

interface ListeningSection {
  type: 'listening';
  id: string;
  title: LocalizedText;
  audio: MediaRef;
  transcript?: TranscriptCue[];  // с таймкодами → подсветка по ходу
  exercises: Exercise[];
}

interface TranscriptCue {
  start: number;   // сек
  end: number;
  en: string;
  ru?: string;
}

// ---------- упражнения ----------
type Exercise =
  | GapFillExercise
  | ChoiceExercise
  | SpotErrorExercise
  | MatchExercise
  | OrderWordsExercise
  | DictationExercise
  | TranslateExercise;

interface ExerciseBase {
  id: string;
  instruction: LocalizedText;   // EN по умолчанию, RU по кнопке
  tags: SkillTag[];             // ["grammar.past-simple", "vocab.work"]
  hint?: LocalizedText;
  explanation?: LocalizedText;  // показывается после ответа
}

interface GapFillExercise extends ExerciseBase {
  type: 'gap-fill';
  prompt: string;               // "Yesterday I ___ the app."
  cue?: string;                 // "(deploy)"
  answers: string[];            // допустимые варианты
  caseSensitive?: boolean;
}

interface ChoiceExercise extends ExerciseBase {
  type: 'choice';
  prompt: string;
  options: string[];
  correctIndex: number;
}

interface SpotErrorExercise extends ExerciseBase {
  type: 'spot-error';
  variants: string[];
  correctIndex: number;
}

interface MatchExercise extends ExerciseBase {
  type: 'match';
  pairs: { left: string; right: string }[];
}

interface OrderWordsExercise extends ExerciseBase {
  type: 'order-words';
  tokens: string[];             // перемешиваются в рантайме
  correctOrder: number[];
}

interface DictationExercise extends ExerciseBase {
  type: 'dictation';
  audio: MediaRef;
  answer: string;               // сверка с нормализацией
}

interface TranslateExercise extends ExerciseBase {
  type: 'translate';
  direction: 'ru-en' | 'en-ru';
  prompt: string;
  answers: string[];            // несколько допустимых
}

// ---------- служебное ----------
interface MediaRef {
  src: string;                  // относительный путь внутри пака
  license: LicenseInfo;         // обязательно
  alt?: LocalizedText;
}

interface LicenseInfo {
  type: 'CC0' | 'CC-BY' | 'CC-BY-SA' | 'public-domain' | 'original' | 'local-only';
  attribution?: string;
  sourceUrl?: string;
}

type SkillTag = string;         // "grammar.past-simple" | "vocab.travel" | "listening.gist"
```

### 4.4 Content Pack: формат и валидация

Пак — это папка:

```
packs/
  dev-english-a2/            ← public pack, в репозитории
    manifest.json
    course.json
    days/
      u01.d01.json
      u01.d02.json
    media/
      audio/
      images/
  my-local-pack/             ← в .gitignore, личный
    ...
```

`manifest.json`:
```json
{
  "id": "dev-english-a2",
  "name": { "en": "English for Developers A2", "ru": "Английский для разработчиков A2" },
  "version": "0.1.0",
  "level": "A2",
  "visibility": "public",
  "license": { "type": "original", "attribution": "Project authors" },
  "attributions": [
    { "source": "VOA Learning English", "license": "public-domain", "url": "https://learningenglish.voanews.com" },
    { "source": "Tatoeba", "license": "CC-BY-2.0-FR", "url": "https://tatoeba.org" }
  ]
}
```

**CLI-валидатор** (`npm run validate:packs`) обязателен и запускается в CI. Проверяет:
- соответствие Zod-схеме;
- уникальность всех ID;
- существование медиа-файлов по указанным путям;
- **наличие непустой лицензии у каждого медиа-объекта**;
- что пак с `visibility: "public"` не содержит объектов с `license.type === "local-only"` (это блокирует случайную публикацию личных материалов).

Последняя проверка — предохранитель. Она должна падать в CI, а не быть предупреждением.

## 5. Функциональные модули

### 5.1 Reading

- Вертикальный текст, абзацы как отдельные блоки.
- **Переключатель RU на уровне абзаца** — кнопка рядом с блоком, не глобальный тумблер. Это прямо соответствует требованию: перевод точечно, там где непонятно.
- **Клик по любому слову** → поповер: перевод, транскрипция, статус (`unknown / learning / known`). Заимствовано у LingQ — их центральная механика. Слова со статусом `learning` подсвечиваются в тексте цветом.
- Добавление слова в SRS одним кликом из поповера.
- Опционально — озвучка абзаца (кнопка play рядом).
- Внизу — glossary секции.

### 5.2 Grammar

- Правило показывается **на двух языках с переключателем EN/RU** (кнопка-сегмент вверху блока). Дефолт — EN, чтобы приучать к английским формулировкам; RU в один клик.
- Формулы-паттерны визуально выделены (моноширинный шрифт, подсветка ключевых частей) — как в прототипе, это хорошо считывается разработчиком.
- Блок **«Типичные ошибки»** — специально для русскоязычных: артикли, порядок слов, `did + past form`, отсутствие связки `be`. Этого нет в оригинальных учебниках (они language-neutral), и это реальная добавленная ценность.
- Примеры кликабельны → добавляются в SRS как grammar-pattern карточки.

### 5.3 Practice — движок упражнений

Один рендерер, семь типов (см. схему 4.2). Три уже реализованы в прототипе (gap-fill, choice, spot-error), четыре добавляем: match, order-words, dictation, translate.

**Обратная связь в стиле test-runner** — сохраняем из прототипа, это фирменная черта: `✓ test passed` / `✕ assertion failed`. Проверено на прототипе, автору нравится, и для целевой аудитории (разработчики) это работает как язык, который они уже знают.

Требования к движку:
- нормализация ответа: trim, схлопывание пробелов, опционально регистр, умные кавычки/апострофы (`don't` vs `don't`);
- несколько допустимых вариантов ответа;
- **не блокировать после ошибки** — давать повторную попытку (прототип так и делает, это правильно);
- после верного ответа — показать `explanation`, если есть;
- каждая попытка пишется в `ExerciseAttempt` с тегами — это топливо для аналитики слабых мест;
- полная клавиатурная навигация: `Enter` — проверить, `Tab` — следующее, цифры `1..4` — выбор варианта. Для целевого пользователя это существенно.

### 5.4 Listening

Это модуль, где стоит вложиться сильнее всего, потому что именно аудирование — самый слабый навык при самостоятельном обучении.

- Плеер с **регулировкой скорости** (0.75 / 1.0 / 1.25) — критично для A2.
- **A-B loop**: выделить фрагмент и зациклить. Ключевая функция для разбора сложных мест.
- **Транскрипт с таймкодами**: подсветка текущей фразы, клик по фразе → перемотка. Транскрипт по умолчанию **скрыт** — открывается кнопкой после первого прослушивания (иначе человек читает, а не слушает).
- **Режим диктанта**: фраза за фразой, пользователь печатает услышанное, показывается diff с эталоном. Это самое эффективное упражнение на аудирование, и оно почти отсутствует в мейнстримных приложениях.
- Параллельный перевод фразы — по кнопке, как в reading.

### 5.5 SRS — интервальные повторения

Используем **FSRS** (Free Spaced Repetition Scheduler) через библиотеку **`ts-fsrs`** — это современный алгоритм, обгоняющий SM-2 из Anki, есть готовая TypeScript-реализация с поддержкой ESM, разработана сообществом Open Spaced Repetition, имеет научное обоснование.

- Карточки создаются автоматически: из glossary, из кликнутых слов, из ошибок в упражнениях.
- Отдельный экран `/review` с очередью на сегодня.
- Оценка 4 кнопками: Again / Hard / Good / Easy (стандарт FSRS).
- Карточка из ошибки помечается тегом → попадает в «работу над ошибками».

### 5.6 Checkpoint-тесты

Идея автора, в учебнике аналога нет — и это правильное дополнение.

- Открывается после прохождения всех дней юнита.
- Собирается **динамически** из пула упражнений юнита + случайных из предыдущих юнитов (interleaving — доказанно эффективнее блочного повторения).
- 15–20 заданий, смешанные типы, обязательно включая listening.
- Результат: общий процент + **разбивка по тегам**: `past simple — 85%`, `irregular verbs — 60%`, `listening.detail — 45%`.
- По итогам генерируется **персональный план повторения**: конкретные дни/секции, к которым стоит вернуться, и карточки, которые доливаются в SRS.
- Тест можно перепройти; хранится история попыток → видна динамика.

### 5.7 Progress & Metrics

Экран `/progress`:
- Стрик и календарь активности (heatmap).
- Время в приложении по дням.
- **Карта навыков**: точность по каждому `SkillTag`, отсортированная по возрастанию — сверху то, что хуже всего. Это главная метрика продукта, ради неё вводились теги.
- Размер активного словаря (`known` + `learning`).
- Прогноз нагрузки SRS на ближайшие дни.
- История чекпоинтов.

Важно по тону: **никаких наказаний за пропуск**. Никаких «сердец», сгорающих стриков с драматизацией, агрессивных пушей. Это известная проблема Duolingo — механики удержания начинают работать против обучения. Стрик показываем как факт, не как угрозу.

## 6. Анализ рынка и заимствования

Что есть на рынке и что конкретно берём.

| Продукт | Сильная механика | Берём / не берём |
|---|---|---|
| **Anki** | Интервальные повторения, полный контроль, открытые форматы | **Берём:** FSRS-планировщик (ts-fsrs), экспорт колод |
| **LingQ** | Клик по слову в тексте → статус слова, подсветка по статусам, рост «известного словаря» как метрика | **Берём:** это ядро reading-модуля |
| **Beelinguapp** | Параллельный текст (два языка рядом) | **Берём в адаптированном виде:** перевод по кнопке на уровне абзаца, а не постоянно рядом (постоянный перевод убивает усилие извлечения) |
| **Memrise** | Аутентичные видео с носителями вместо синтетической речи | **Заимствуем принцип:** для listening приоритет живой речи (VOA) над TTS |
| **Duolingo** | Геймификация, короткие сессии, привычка | **Берём:** дневная структура, стрик. **Не берём:** сердца/жизни, агрессивные уведомления, лидерборды |
| **Busuu** | Чёткая привязка к уровням CEFR, структурность | **Берём:** явная маркировка CEFR-уровня каждой темы |
| **LibreLingo** | Open source, декларативный формат курсов, курсы как данные | **Берём:** философию «контент = данные», изучить их формат курса как референс схемы |
| **LinguaCafe** | Self-hosted, пользователь приносит свой контент | **Берём:** ровно эту модель (раздел 1.3) |
| **Pimsleur** | Аудио-первый подход, интервальное припоминание вслух | **Заимствуем идею:** режим shadowing в v2 |

**Чего на рынке нет и что делает наш продукт уникальным:**
1. Профессионально-специфичный контент (примеры из мира разработки) на уровне A2 — ниша пустая.
2. Точечное двуязычие (EN/RU переключается поблочно, а не глобально) — обычно приложения либо полностью на языке-цели, либо полностью переводные.
3. Диктант-режим для аудирования — редкость в мейнстриме.
4. Карта навыков по тегам вместо абстрактных «очков опыта».
5. Работа с собственными материалами пользователя + честная лицензионная модель.

## 7. AI-слой

### 7.1 Позиционирование

AI — **опциональный помощник, не ядро**. Приложение обязано быть полностью работоспособным без него. В v1 закладываем интерфейс и минимальный набор функций; расширяем в v2.

### 7.2 Модель доступа: BYOK (Bring Your Own Key)

Единственно правильный вариант для open source-проекта без бэкенда: ключ вводит сам пользователь в настройках, ключ хранится локально, запросы идут напрямую к провайдеру. Никаких общих ключей в репозитории, никаких затрат на нас.

**Провайдеры, поддерживаемые через один OpenAI-совместимый интерфейс:**

По состоянию на середину 2026 бесплатные тиры реальны и достаточны для личного использования:
- **Google AI Studio (Gemini)** — бесплатный тир без кредитной карты, Gemini 2.5 Flash, мультимодальность (текст/изображения/аудио), большой контекст. Лучший вариант «по умолчанию» для нашего кейса.
- **Groq** — очень быстрый инференс на открытых моделях (Llama, Qwen), высокий дневной лимит, OpenAI-совместимый API. Хорош для мгновенных подсказок.
- **OpenRouter** — один ключ, десятки бесплатных моделей, удобен как fallback.
- Любой платный ключ (OpenAI / Anthropic / etc.) — через тот же интерфейс.

**Обязательное предупреждение в UI:** бесплатные тиры почти всегда означают, что запросы могут использоваться для обучения моделей. Для нашего кейса (учебные предложения) это некритично, но пользователь должен знать. Показываем это в настройках при выборе провайдера, без мелкого шрифта.

**Реализация:** абстракция `AiProvider` с методом `complete(prompt, opts)`, конкретные адаптеры под провайдеров, все запросы идут через один слой с обработкой rate limit и экспоненциальным backoff. Все бесплатные тиры жёстко лимитированы по RPM — без backoff приложение будет спамить ошибками.

### 7.3 AI-функции (по приоритету)

**v1 (минимум):**
1. **Объяснить ошибку.** Кнопка после неверного ответа: «почему неправильно?» — контекст: предложение, ответ пользователя, правильный ответ, тема. Ответ на выбранном языке интерфейса.
2. **Подсказка без ответа.** Наводящая мысль, не решение. Промпт явно запрещает выдавать готовый ответ.
3. **Разбор слова в контексте.** Из поповера в reading: значение именно в этом предложении, а не словарная статья.

**v2:**
4. **Генерация дополнительных упражнений** по слабым тегам из карты навыков — «дай мне ещё 5 заданий на past simple с неправильными глаголами».
5. **Проверка свободного письма.** Пользователь пишет текст (например, сообщение в рабочий чат), AI возвращает исправления с объяснениями. Прямо закрывает заявленную цель «грамотная переписка».
6. **Диалог-тренажёр** на тему дня с ролевой ситуацией.

**Правила для всех AI-функций:**
- graceful degradation: нет ключа / нет сети / лимит исчерпан → кнопка неактивна с понятным объяснением, остальное приложение работает;
- ответ всегда помечен как сгенерированный AI;
- факт использования AI пишется в `ExerciseAttempt.usedAI` (влияет на честность метрик);
- кэширование ответов по хешу промпта — экономит лимиты при повторных запросах.

## 8. Дизайн-система

Основана на прототипе, одобренном автором. Эстетика: тёмный «редакторский» интерфейс, обратная связь на языке инструментов разработчика.

### 8.1 Принципы

1. **Терминальная честность.** Обратная связь выглядит как вывод тест-раннера. Не празднуем каждый правильный ответ конфетти — сообщаем результат.
2. **Моноширинный = язык-цель.** Английские слова, формы глаголов, формулы грамматики набираются моноширинным. Интерфейсный текст — гротеском. Это создаёт мгновенное визуальное разделение «изучаемое / служебное».
3. **Один акцент за раз.** Teal — успех и прогресс, amber — внимание и грамматические маркеры, coral — ошибка. Больше акцентных цветов не вводим.
4. **Плотность выше воздушности.** Целевой пользователь привык к IDE. Компактнее, чем типичное обучающее приложение, но с чётким ритмом.

### 8.5 Обязательный «пол качества»

Не обсуждается, проверяется в ревью каждого компонента:
- адаптив от 360px;
- видимый focus-ring на всех интерактивных элементах (`outline-2 outline-teal outline-offset-2`);
- `prefers-reduced-motion` отключает все анимации;
- контраст текста ≥ 4.5:1 (проверить `--color-muted` на `--color-surface`);
- все интерактивные элементы достижимы с клавиатуры, порядок табуляции логичен;
- ARIA: упражнения — `role="group"` с `aria-label`, обратная связь — `aria-live="polite"`.

### 8.6 Открытый вопрос: светлая тема

Прототип тёмный. Для чтения длинных текстов часть людей предпочитает светлую тему. Решение: спроектировать токены как семантические (что уже сделано — `--color-ink`, а не `--color-black`), и добавить светлую палитру в v2 через `data-theme`. В v1 — только тёмная, не тратим время.

## 10. Дорожная карта — этапы для агента

Этапы упорядочены так, чтобы после каждого было что-то работающее.

## 11. Открытые вопросы

1. **Объём контента для Public Pack.** Написать оригинальный курс на 12 юнитов — это большая работа. Реалистичный план: сначала 1–2 юнита вручную как эталон качества, дальше — генерация черновиков через AI с обязательной ручной вычиткой. Оценить трудозатраты до старта M2.
2. **Локальный пак: способ импорта.** File System Access API (Chrome) даёт удобную работу с папкой, но нет в Safari/Firefox. Альтернатива — загрузка zip-архива и распаковка в IndexedDB. Вероятно, нужны оба пути.
3. **Формат тегов навыков.** Нужен фиксированный словарь тегов, иначе аналитика развалится. Составить справочник `SkillTag` до M3.
4. **Русские переводы.** Кто пишет `ru`-версии? Для собственного контента — автор. Для Tatoeba переводы часто уже есть. Заложить, что `ru` опционально и UI это корректно переживает.
5. **Лицензия проекта.** Рекомендую разделить: код — MIT, контент Public Pack — CC BY-SA. Это стандартная схема для образовательных open source-проектов и она предотвращает недоразумения.

## Приложение A — прототип

Референс-реализация одного урока (Past Simple) существует в виде самодостаточного HTML-файла. Она задаёт:
- визуальный язык (цвета, типографика, плотность);
- паттерн обратной связи в стиле test-runner;
- три типа упражнений (gap-fill, choice, spot-error);
- механику флеш-карточек с переворотом;
- прогресс-бар по решённым заданиям.

Агенту следует воспринимать прототип как источник истины по визуалу и микровзаимодействиям, а этот документ — как источник истины по архитектуре и объёму.
