# Content Forge — автоматический сбор контента

Слой между открытыми источниками и нашей JSON-схемой. Задача: агент собирает день обучения из свободных материалов сам, а лицензии проставляются автоматически и не могут быть забыты.

Всё, что здесь используется, **бесплатно и без платных тарифов**. Ключи нужны только для LLM-генерации, и там бесплатных тиров хватает с запасом.

---

## 1. Ключевой принцип: лицензия проставляется инструментом, а не агентом

Главная проблема автоматизации — агент забудет атрибуцию. Не «может забыть», а забудет: через двадцать вызовов подряд модель начнёт оптимизировать вывод и выкинет поле, которое ей кажется служебным.

Поэтому **лицензия не является параметром, который агент заполняет**. Каждый source-адаптер возвращает данные вместе с уже собранным `LicenseInfo`, а `pack.write_day` отклоняет запись, если у медиа нет лицензии. Агент физически не может создать ассет без происхождения.

```
источник → адаптер (пришивает license) → агент компонует → writer (проверяет license) → JSON
```

Это тот же предохранитель, что и в CLI-валидаторе из M2, но сдвинутый на шаг раньше — на момент создания, а не публикации.

## 2. Источники и способ доступа

| Источник | Что даёт | Доступ | Лицензия | Ключ |
|---|---|---|---|---|
| **Tatoeba** | Предложения EN + переводы RU, часть с аудио | Еженедельные дампы CSV → локальный SQLite | CC BY 2.0 FR (аудио — на выбор автора записи) | нет |
| **VOA Learning English** | Тексты + mp3 + транскрипты, уровневые | RSS-фиды, затем страница статьи | Public domain | нет |
| **Free Dictionary API** | Определения, IPA, произношение | `api.dictionaryapi.dev/api/v2/entries/en/{word}` | производное от Wiktionary (CC BY-SA) | нет |
| **Openverse** | Картинки под CC/PD, 800M+ работ | `api.openverse.org/v1/images` | CC / public domain, фильтр по типу | нет (анонимно) |
| **Wikimedia Commons** | Произношение слов, изображения | MediaWiki API | CC / PD | нет |
| **NGSL** | Частотный список (~2800 слов) | CSV-скачивание | открытая | нет |
| **Piper / Kokoro** | TTS, американский акцент | локально, ONNX | открытая модель | нет |
| **Whisper** | Транскрипция и таймкоды | локально | MIT | нет |
| **Gemini / Groq** | Генерация текстов и упражнений | HTTP | — | бесплатный тир |

### Замечания по каждому

**Tatoeba — брать дампы, не API.** Публичного стабильного API у проекта фактически нет (он годами в состоянии «обсуждается»), зато есть еженедельные экспорты: `sentences.csv`, `links.csv`, `sentences_with_audio.csv`. Заливаешь в SQLite один раз, дальше поиск локальный и мгновенный. Аудио лежит по предсказуемому адресу `https://audio.tatoeba.org/sentences/eng/{id}.mp3`.

Критично: **лицензия аудио у Tatoeba выбирается конкретным диктором** и отличается от лицензии текста. В `sentences_with_audio.csv` есть поле лицензии — адаптер обязан его читать и отсекать записи без явной открытой лицензии, а не считать, что раз текст CC BY, то и звук тоже.

**VOA — RSS.** Официального API нет, но есть фиды по разделам, а материалы в общественном достоянии, так что переиспользование не ограничено. Правила приличия всё равно соблюдаем: свой User-Agent, пауза между запросами, уважение robots.txt, кэш на диск, чтобы не дёргать одну страницу дважды.

**Openverse — анонимный доступ работает без ключа**, отдаёт до 240 результатов на запрос (20 на страницу, 12 страниц). Нужен внятный User-Agent и обработка 429 с backoff. Фильтр по лицензии задаётся параметром — ставим `license=cc0,by` и не связываемся с SA/NC там, где это усложнит жизнь.

**NGSL — не источник контента, а фильтр уровня.** Каждое слово получает ранг частотности; всё, что за пределами первых ~2000, для A2 не годится. Это объективный критерий, который заменяет интуицию «сложно ли это слово».

## 3. MCP-сервер: состав инструментов

Локальный сервер на TypeScript, подключается к Claude Code / Claude Desktop. Агент вызывает инструменты, компонует день, записывает в пак.

### Источники

- **`tatoeba_search`** — `{ query?, grammarPattern?, maxNgslRank?, requireAudio?, requireRussian?, limit }` → предложения с переводом, лицензией и ссылкой на аудио. Фильтр по NGSL встроен: запрос «дай предложения с past simple не сложнее A2» отрабатывается одним вызовом.
- **`voa_list`** / **`voa_fetch`** — список свежих материалов по разделу и загрузка конкретного: текст, mp3, транскрипт.
- **`dict_lookup`** — `{ word }` → IPA, значения, примеры, аудио произношения.
- **`image_search`** — `{ query, license }` → картинки Openverse с готовой строкой атрибуции.
- **`ngsl_rank`** — `{ words[] }` → ранг каждого слова. Используется как проверка уровня для любого текста, включая сгенерированный.

### Обработка

- **`tts_synthesize`** — `{ text, voice, speed }` → mp3 локальным Piper/Kokoro. Лицензия `original`, потому что текст наш.
- **`align_transcript`** — `{ audioPath, text }` → массив `TranscriptCue` с таймкодами. Форсированное выравнивание, когда текст известен; Whisper, когда нет.
- **`level_check`** — `{ text, targetLevel }` → отчёт: доля слов вне уровня, средняя длина предложения, найденные грамматические конструкции выше уровня. Возвращает конкретные слова-нарушители, чтобы агент переписал, а не гадал.

### Сборка

- **`pack_write_day`** — принимает готовую структуру дня, валидирует по Zod-схеме, скачивает медиа в пак, проставляет лицензии, пишет JSON. **Отклоняет всё, у чего нет `LicenseInfo`.**
- **`pack_validate`** — обёртка над CLI-валидатором из M2.

## 4. Типовой сценарий работы агента

Промпт: «собери день по теме past simple, уровень A2, тематика — работа разработчика».

1. `ngsl_rank` — агент проверяет свой черновик лексики на уровень.
2. Генерация текста для reading (LLM) → `level_check` → правки, пока не пройдёт порог.
3. `image_search` — иллюстрация к тексту, лицензия приходит вместе с картинкой.
4. `tts_synthesize` — озвучка текста и отдельных фраз для диктанта.
5. `align_transcript` — таймкоды для транскрипта.
6. `tatoeba_search` — готовые предложения с past simple и русским переводом → упражнения `translate` и `gap-fill`.
7. `voa_list` + `voa_fetch` — аутентичный материал для listening как контраст к синтетике.
8. `dict_lookup` — IPA и значения для glossary.
9. `pack_write_day` — сборка и запись.
10. `pack_validate` — финальная проверка.

День собирается за один диалог. Ручная работа остаётся только там, где она действительно нужна: вычитка сгенерированного текста и проверка, что упражнения не бессмысленны.

## 5. Что автоматизировать нельзя

Честно про границы, чтобы не было разочарования:

**Вычитку.** LLM на A2-уровне регулярно выдаёт предложения, формально верные, но неестественные. «The developer performed a deployment» вместо «She deployed the app». Уровень слов пройдёт проверку по NGSL, а звучать будет как перевод с русского. Глазами смотреть придётся.

**Качество дистракторов.** В multiple choice неправильные варианты должны быть правдоподобными и отражать типичные ошибки. Модель часто генерирует либо очевидно абсурдные, либо случайно тоже верные. Это место, где ручной проход окупается.

**Грамматические объяснения.** Их проще написать один раз самому, чем чинить сгенерированные. Тем более что блок «типичные ошибки русскоязычных» модель без специального промпта не придумает — она не знает, что именно ломается у носителя русского.

Реалистичное распределение: **сбор и обвязка — автоматом, смысловой контроль — руками**. Это всё равно на порядок быстрее ручного набора.

## 6. Порядок реализации

1. **Tatoeba → SQLite.** Скрипт скачивания дампов и импорта. Самая большая отдача на единицу усилий: сразу появляется десятки тысяч готовых предложений с русским переводом.
2. **NGSL-фильтр.** Маленький модуль, но без него нет контроля уровня, а без контроля уровня генерация бесполезна.
3. **MCP-сервер с этими двумя инструментами.** Проверить сквозной сценарий на одном дне.
4. **TTS + выравнивание.** Локальные модели, разовая настройка.
5. **VOA и Openverse.** Сетевые адаптеры с кэшем и вежливым троттлингом.
6. **`pack_write_day`.** Пишется последним, когда понятно, какие данные реально приходят.

---

## 7. Кэш и повторяемость

Все сетевые ответы кэшируются на диск по хешу запроса. Причины две: не долбить бесплатные публичные API при отладке и получать воспроизводимый результат при повторной сборке дня. Кэш — в `.cache/`, в `.gitignore`.

Скачанные медиа складываются в пак сразу с финальными именами (`uXXdYY-<что>.<ext>`), чтобы не было отдельного шага «разложить файлы».
